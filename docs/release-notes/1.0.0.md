# 1.0.0

First release of `@naskot/node-hmac-auth-core`. Epured fork of `@naskot/node-hmac-auth` 1.4.0.

## What this release IS

A pure HMAC auth library:

- HTTP track: sign outbound requests (`createHttpSignedFetchClient`), verify inbound
  requests (`verifyHttpRequest`, `verifyHttpSignature`, Express / Connect-compatible
  middleware `createExpressHttpHmacMiddleware` / `createHttpHmacMiddleware`).
- Message track: sign and verify arbitrary payloads outside HTTP
  (`signMessage` / `verifyMessage`).
- Credentials CRUD on both tracks (`clients.create` / `get` / `listClientIds` /
  `delete` / `regenerateSecret` / `setSecret` / `setSecretHash` / `setAllowedIps` /
  `getSecretHash` / `revert`).
- Redis credential store + nonce store, namespacing helpers, byte-identical to upstream.
- TTL backup written on every rotation so `clients.revert(clientId)` can roll back
  to the previous secretHash inside `dbSeedBackupTtlSeconds` (default 600s).
- `createHmacRuntime(...)` aggregate helper.
- All canonical primitives (`hashClientSecret`, `hashBody`, `safeEqualHex`,
  `signRequest`, `buildSigningPayload`, `buildHttpSignedHeaders`,
  `buildMessageSigningPayload`, `captureRawBody`, `signedHttpFetch`).
- `HmacAuthError` with 14 typed codes.

## What this release is NOT

The credential-propagation layer of upstream is gone. It is extracted into the
companion package `@naskot/node-hmac-auth-core-propagation`. This fork is the
auth primitives only.

## Migration from `@naskot/node-hmac-auth` 1.4.0

Rename your import:

```ts
- import { initializeHmacHttpAuth } from "@naskot/node-hmac-auth";
+ import { initializeHmacHttpAuth } from "@naskot/node-hmac-auth-core";
```

Drop these init options if you used them (they were all propagation-only):

| Removed option                     | Where                                                                        |
| ---------------------------------- | ---------------------------------------------------------------------------- |
| `internalManagementRoute`          | `initializeHmacHttpAuth`                                                     |
| `requireBootstrapClientId`         | `initializeHmacHttpAuth`, `initializeHmacMessageAuth`, `verifyHttpSignature` |
| `messageAuth` (cross-track bridge) | `initializeHmacHttpAuth`                                                     |

Drop these methods if you called them:

| Removed method                                        | Replacement                                             |
| ----------------------------------------------------- | ------------------------------------------------------- |
| `auth.propagateClientToApis(...)`                     | use `@naskot/node-hmac-auth-core-propagation`           |
| `auth.handleInternalManagementRequest(...)`           | expose your own admin endpoint or use the companion lib |
| `auth.createInternalManagementMiddleware(...)`        | same                                                    |
| `auth.createExpressInternalManagementMiddleware(...)` | same                                                    |
| readonly `auth.internalManagementRoute`               | gone                                                    |

Drop these fields if you read them on records:

| Removed field | On                                                                              |
| ------------- | ------------------------------------------------------------------------------- |
| `fromDbSeed?` | `HmacClientCredential`, `CreateHmacClientOptions`, `HmacCredentialWriteOptions` |
| `purpose?`    | same + `HmacCredentialPurpose` type                                             |

Drop these CRUD write-option params:

| Method                  | Before                                                  | After                                         |
| ----------------------- | ------------------------------------------------------- | --------------------------------------------- |
| `clients.setSecret`     | `(clientId, secret, expiresAt?, allowedIps?, options?)` | `(clientId, secret, expiresAt?, allowedIps?)` |
| `clients.setSecretHash` | `(clientId, hash, expiresAt?, allowedIps?, options?)`   | `(clientId, hash, expiresAt?, allowedIps?)`   |

The `options` parameter only carried `fromDbSeed` and `purpose`, both gone.

Drop these error codes from any switch / matcher:

| Removed code                 |
| ---------------------------- |
| `INTERNAL_ROUTE_DISABLED`    |
| `PROPAGATION_ONLY_FORBIDDEN` |
| `BOOTSTRAP_LOCKED`           |

Drop these types from any import block:

`HmacInternalManagementRequestInput`, `HmacInternalManagementRequestResult`,
`HmacInternalPropagationOperation`, `HmacPropagateTargetStore`,
`PropagateHmacClientOptions`, `PropagateHmacClientResult`,
`PropagateServiceCreateOptions`, `PropagateServiceUpdateOptions`,
`PropagateServiceDeleteOptions`, `PropagateServiceHealthOptions`,
`HmacCredentialPurpose`, `HmacMessageAuthBridge`, `HmacCredentialWriteOptions`.

## Wire compatibility

The HMAC wire (`hashClientSecret`, `buildSigningPayload`, `signRequest`,
required headers, Redis record JSON, nonce TTL semantics, error codes used by the
auth verifier) is **byte-identical** to upstream 1.0.x through 1.4.0. Cross-language
ports keep interoperating with Node consumers without change. See
[`docs/wire-contract.md`](../wire-contract.md).

The behavior changes affect only:

- The bootstrap-window lock is gone. A fresh install of this fork accepts requests
  immediately (assuming a credential is stored). Upstream 1.4.0 required the
  `requireBootstrapClientId` record to exist first.
- The `purpose: "propagation-only"` cantonment is gone. A credential authenticates
  every signed request that matches its hash.
- The internal management route is gone. There is no `/api/internal/hmac` or any
  equivalent built into the lib.

## Companion package

For credential propagation between peers over RabbitMQ, see
`@naskot/node-hmac-auth-core-propagation`. It consumes this lib as a peer dep
and ships the orchestration the upstream propagation layer used to provide.
